## Killed or withdrawn claims
K1–K11 are withdrawn v1 findings. K12 is not a finding: it records an editorial removal.

| # | Claim (v1 wording, paraphrased) | Why it is killed | Evidence |
|---|---|---|---|
| K1 | "The decision model is better" (than general LLMs, or than simple ML), as a general claim | On structured data, in-context examples ≈ logistic regression on the same labels (significantly better on 0/8 at k=50–200). Frontier LLMs had lower Brier on most tasks. | docs/REVIEW_2026-09-27.md |
| K2 | "One sentence stating the base rate fixes most of the miscalibration" | Told beat simply predicting the stated rate (a constant) on only 2/8 tasks. The claim was measured against zero-shot, not against the trivial baseline. | results/v1/baseline_audit.md (A) |
| K3 | All Opus 5.5 results (zero-shot AUROC 0.87 on GitHub; "Opus beats Jev on 7/8") | The provider route varied by task (Anthropic vs OpenRouter), with cache keys ignoring the route. Contamination was unchecked (Opus cutoff June 2026; data Jan–Aug 2026). Opus's GitHub AUROC beat a per-repo-rate oracle. Not re-run in v2; withdrawn. | docs/REVIEW_2026-09-27.md |
| K4 | Shelter results (e.g. in-context AUROC 0.64 → 0.84) | Label leak: `sex` (spay/neuter status) is recorded after the outcome, and alone gives CV AUROC 0.78. The v2 repair drops it, and the zero-shot AUROC of the decision model falls to 0.53. | src/v2/leak_audit.py, results/v2/e1_tests.csv |
| K5 | GitHub PR results that rely on the "draft" marker | `draft` is the state at closing (0/48 drafts merged). Repaired in v2. Titles may also have been renamed at merge (not repairable); the sample is the top 200 by relevance, not random. | docs/REVIEW_2026-09-27.md |
| K6 | Crimes AUROC 0.78 zero-shot | Inflated by police-initiated offence types that exist because of an arrest (narcotics 98%). On repaired v2 data it is 0.68 for the same model. | results/v2/e1_tests.csv |
| K7 | "Gemini beats Jev zero-shot on 6/8" as evidence of model quality | These are the same 6 tasks where a constant beats Jev. It is a base-rate effect, not better ranking. | docs/REVIEW_2026-09-27.md |
| K8 | Synthetic tasks: "LR gets 7–8× closer to the truth" | That is an MSE ratio (≈2.8× in RMSE), and LR is the correctly specified model for data generated by a logistic model. | docs/REVIEW_2026-09-27.md |
| K9 | "Stack, don't stuff": the LLM score helps TabPFN | The LLM score doesn't significantly help TabPFN on 7/8; the wins were TabPFN's own. | docs/REVIEW_2026-09-27.md |
| K10 | "Platt matters most with noisy labels"; "split the labels when over the context limit" | Never tested (noisy + Platt not run; the context limit was never exceeded). | docs/REVIEW_2026-09-27.md |
| K11 | "Shuffled-label control shows learning on 8/8" | In-context minus zero-shot AUROC is significant on only 5/8 (not crimes, flights or HN). | docs/REVIEW_2026-09-27.md |
| K12 | *(Editorial, not a finding.)* Evaluative remarks about the decision model's vendor | Out of scope for a neutral guide. Removed by user decision. | — |

## Independent re-verification (2026-09-30)
`verification/recompute_claims.py` recomputes V1, V2, V3, V8, V11, the 117-cell counts, S3 and S4 from the saved
per-item predictions without importing the analysis code (independent bootstrap indices per task, different RNG).
Output: `verification/recompute_output.txt`.
- Every v2 point estimate and per-seed estimate in README.md, results/v2/replication_table.md and
  results/v2/extensions_e2_e3.csv matches to the printed precision. Every Holm decision is unchanged. The counts
  47 / 0 of 117, V3's 2/9, and V8's 5 cells reproduce exactly.
- Two confirmatory cells are marginal (p ≈ 0.03 over 30 bootstrap seeds and an analytic z-test): Gemini told − shift
  (E1-R) and Jev told − constant (E1-R). Both pass Holm only because each is the largest p in its family.
- Re-running `src/v2/baserate_analyze.py` (E1, E1-R, E2, E3) and `src/v2/final_tables.py` reproduced every committed
  file in `results/v2/` byte for byte.
- Minor analysis note: `src/v2/baserate_analyze.py` reuses one bootstrap index matrix for every task and model, so the
  "within task" resamples are not independent across tasks. With independent indices the CIs change only in the third
  decimal and no conclusion changes.
- `results/v2/extensions_e2_e3.csv` has no generating script in the repo (it was assembled from the `_e2`/`_e3`
  outputs); its numbers match the recompute.
